# 0.6.0

Released 2026-10-06.

- bioeksen-sds-20261006T150705-7137 feat(logging)!: BREAKING CHANGE: a write naming a related record that does not exist is 400 VAL-4006, a write setting a unique key another record holds is 409 RES-4300, and an operation not implemented yet is 500 SYS-5000, never 501. A service answering any of these differently no longer conforms.
  - What changed: clarify selection steps 19, 21 and 22, add a Database failures table naming the step each usual driver failure meets, checked by invariant 2, rule that an unimplemented operation is `SYS-5000`, and add their contract cases
- bioeksen-sds-20261006T150733-2327 feat(api-design)!: BREAKING CHANGE: an endpoint that takes a body must now refuse one over 1 MiB with 413 VAL-4550, unless the app records a different limit for it, and must count the limit on the bytes received rather than trust Content-Length.
  - What changed: set the default body limit to 1 MiB, the aggregator's batch limit, as an empirical value an app may change and must record, and add the contract cases
- bioeksen-sds-20261006T150853-2e14 feat(logging)!: BREAKING CHANGE: a record must carry no stack trace, a failure's own text and its causes must go under the error and cause keys, a record the local store fails to write is logged under that store's code rather than a LOG- code, and the lowest severity emitted is set by LOG_LEVEL, INFO when unset.
  - What changed: send stacks to stderr keyed by code and request, reserve the `request`, `job`, `attempt`, `error` and `cause` tail keys and require library text to be redacted, give the two local logging failures their codes, and name `LOG_LEVEL`
- bioeksen-sds-20261006T151105-f48f feat(config)!: BREAKING CHANGE: an app must validate its whole configuration at startup and must not report ready while a value is missing or unusable, must declare every value in a committed example file, and must refuse a test seam's setting in production.
  - What changed: add the `sds-config` skill and its contract cases, and invariant 12, which keeps README's Skills table to exactly the skills
- bioeksen-sds-20261006T151203-695c feat(testing)!: BREAKING CHANGE: a tier that could not run must fail CI, a suite that creates or empties a database must refuse any target that is not disposable, and a test seam must be refused in production.
  - What changed: add known defects as strict expected failures with a precondition beside them, the rules against weakened tests, flaky and not-run reporting, tiers and sources, guarded test databases, and seams that fail closed
- bioeksen-sds-20261006T150526-592c feat(kit): a new service's first release has no earlier tag, so the release note check stopped and asked for --previous, and nothing said which version a first release is
  - What changed: check a first release over every commit from the root, expect `0.1.0`, and state that rule in `sds-commit`
- bioeksen-sds-20261006T150913-6561 feat(logging): a bundled, standalone or serverless build ships without `.bioeksen/software-id`, so such an app had either to break the rule or copy the id by hand where nothing kept it right
  - What changed: allow a compiled-in copy of the id, generated from the file or held equal to it by a test, and add the contract case that catches a stale one
- bioeksen-sds-20261006T151223-ef4b docs: the roadmap's decision table did not yet hold the rulings this release lands, nor where they came from
  - What changed: add a decision row for each, with its commit

Styling and component reference for a Next.js project built on HeroUI v3, Tailwind CSS v4 and a Fluent-style palette. Every value on this page is read from the project's stylesheet at load time, so it shows this project's palette and contrast ratios, not the ones it was written with.

Scoped class is the class the project uses to re-theme a region (a dark sidebar, say). It is applied to the dark panels below and to the second column of the contrast table. Leave it empty if the project has none.

Palette

The only source of colour. Two ramps, each slot a CSS variable in the global stylesheet and a Tailwind utility through @theme (--theme-primary → bg-theme-primary). Each swatch shows white and black text on it, with both ratios below. Slots marked not defined are Fluent slots the project has not declared.

Brand ramp, dark → light

Neutral ramp

Trap: Tailwind's own neutral-50 … neutral-950 scale shares the prefix and still compiles. bg-neutral-100 is a new colour; bg-neutral-lighter is the palette.

Semantic tokens

HeroUI components are coloured through these tokens, and the global stylesheet maps each one onto a palette slot. Style your own markup with the same tokens. A scoped class and the dark theme re-point tokens; a ramp utility stays the same colour, so it is the one that breaks.

TokenUtilityForValuePalette slot

A token has a utility only if HeroUI registers it as --color-*, and the utility follows that name: --field-background is bg-field. A class naming anything else (bg-field-background) generates no CSS and no warning.

A field's border needs a width as well as a colour. HeroUI draws it at --field-border-width, which it sets to 0px, and makes --field-border transparent. Setting the colour alone draws nothing: set both, for example --field-border: var(--neutral-secondary); --field-border-width: 1px;. The contrast table counts a border only when it is drawn.

Contrast (WCAG 2.1 AA)

Measured live from the tokens: 4.5:1 for text, 3:1 for large text (24px, or 18.66px bold) and for what identifies a control (1.4.11). Translucent tokens (the soft variants) are composited over the surface first, as the browser draws them. Switch the theme above to measure the dark theme.

A pairing not in this table is measured before it ships: ratio = (Llighter + 0.05) / (Ldarker + 0.05), L being relative luminance. WCAG does not round: 4.49 fails.

Components

HeroUI v3 only, compound API (<Card><Card.Header>), onPress not onClick, no provider except the locale one. Previews are real HeroUI output; write the JSX. Fetch a component's docs before using it: node .claude/skills/heroui-react/scripts/get_component_docs.mjs Button.

In the snippets, t is the dictionary, getI18n() / useI18n() read it on the server and client, fmt() fills {name} placeholders and errorMessage() turns an error code into a sentence. They stand in for whatever the project's own i18n layer calls them; the project's conventions say where it lives.

Form posting to a server action (React 19)

"use client";

type FormState = { result: ActionResult | null; saved: number };

export function RecordForm({ action }: { action: (fd: FormData) => Promise<ActionResult> }) {
  const { t } = useI18n();
  const [state, submit, pending] = useActionState(
    async (previous: FormState, formData: FormData): Promise<FormState> => {
      const result = await action(formData);
      return { result, saved: previous.saved + (result.ok ? 1 : 0) };
    },
    { result: null, saved: 0 },
  );
  // The server's field errors, keyed by field name.
  const fields = state.result && !state.result.ok ? state.result.fields : {};
  const formRef = useRef<HTMLFormElement>(null);

  // Focus goes where the user acts next, once per result.
  useEffect(() => {
    const form = formRef.current;
    if (form === null || state.result === null) return;
    if (state.result.ok) {
      // Success: the re-keyed fields are fresh; start again at the first one.
      form.querySelector<HTMLElement>("input, textarea, select")?.focus();
      return;
    }
    const invalid = form.querySelector<HTMLElement>('[aria-invalid="true"]');
    if (invalid !== null) {
      invalid.focus(); // its error is its description: label and error are read together
      return;
    }
    // A whole-form rejection: back to Save (disabling it while pending can drop
    // focus), with the alert in view.
    form.querySelector<HTMLElement>('button[type="submit"]')?.focus();
    form.querySelector('[role="alert"]')?.scrollIntoView({ block: "nearest" });
  }, [state]);

  return (
    // HeroUI's Form, not a bare <form>. validationBehavior="aria": the default,
    // "native", hands validation to the browser, which then blocks submits by
    // itself. An empty required field is refused with no visible error, and after
    // the server rejects a field, the form cannot be submitted again until reload.
    <Form
      ref={formRef}
      validationBehavior="aria"
      validationErrors={fields}
      onSubmit={(event) => {
        // Not <form action={fn}>: React 19 resets uncontrolled fields before
        // the action runs, so a rejected submit would wipe the user's input.
        event.preventDefault();
        const formData = new FormData(event.currentTarget);
        startTransition(() => submit(formData)); // outside a transition, pending never turns true
      }}
    >
      {/* Announce the result. A rejection is read at once. */}
      {state.result && !state.result.ok ? (
        <Alert status="danger" role="alert">…</Alert>
      ) : null}
      {/* A success waits its turn. The status region is always rendered: some
          screen readers announce it only if it exists before its text does. */}
      <div role="status">
        {state.result?.ok ? <Alert status="success">…</Alert> : null}
      </div>

      {/* Reset after success by re-keying, not form.reset(): child state survives reset(). */}
      <div key={state.saved}>
        {/* isRequired marks the field (aria-required, asterisk); the server enforces it. */}
        <TextField name="code" isRequired>
          <Label>{t.form.code}</Label>
          <Input />
          <FieldError />   {/* shows fields.code; clears when the user edits the field */}
        </TextField>

        {/* A value React Aria does not own (a hidden input a custom picker fills)
            reads its error from the result itself. */}
        <FolderPicker name="folderId" error={fields.folderId} />
      </div>
      <Button type="submit" variant="primary" isDisabled={pending}>
        {pending ? t.form.saving : t.form.save}
      </Button>
    </Form>
  );
}

// Don't drive isInvalid from server errors: a controlled isInvalid stays set
// until the next result, and with native validation it blocks that result.
// No client-side re-validation: the server validates and returns field errors.
// Files never go through a server action (1 MB body limit): upload them to a
// route handler first and put only the handle in the form.
// Tests click the submit Button; fireEvent.submit skips the browser's own
// validation and cannot catch a form that refuses to submit.

Table from a server component

// HeroUI's Table builds its collection from its children, and functions cannot
// cross the server/client boundary. So the server passes data, and a small client
// wrapper builds Table.Row / Table.Cell. Cell contents may be ReactNode: plain
// element trees (Chip, Meter) do cross the boundary.

"use client";
export type DataTableColumn = { key: string; label: string; width?: number;
  isRowHeader?: boolean; cellClassName?: string };
export type DataTableRow = { id: string; href?: string; cells: Record<string, ReactNode> };

export function DataTable({ ariaLabel, columns, rows, className }: {
  ariaLabel: string; columns: readonly DataTableColumn[];
  rows: readonly DataTableRow[]; className?: string;
}) {
  return (
    <Table>
      <Table.ScrollContainer>
        <Table.Content aria-label={ariaLabel} className={className}>
          <Table.Header>
            {columns.map((c) => (
              <Table.Column key={c.key} id={c.key} isRowHeader={c.isRowHeader} width={c.width}>
                {c.label}
              </Table.Column>
            ))}
          </Table.Header>
          <Table.Body>
            {rows.map((row) => (
              <Table.Row key={row.id} id={row.id} href={row.href}>
                {columns.map((c) => (
                  <Table.Cell key={c.key} className={c.cellClassName}>{row.cells[c.key]}</Table.Cell>
                ))}
              </Table.Row>
            ))}
          </Table.Body>
        </Table.Content>
      </Table.ScrollContainer>
    </Table>
  );
}

A form that stops submitting

// Don't: a bare form, with server errors driving isInvalid.
// Validation defaults to "native": an empty isRequired field blocks the
// submit with no visible error, and once the server rejects "code" the
// browser refuses every later submit, even after the user fixes it.
<form onSubmit={onSubmit}>
  <TextField name="code" isRequired isInvalid={fields.code !== undefined}>
    <Label>{t.form.code}</Label><Input />
    <FieldError>{fields.code}</FieldError>
  </TextField>

// Do: HeroUI's Form, aria validation, server errors by field name.
// Every submit reaches the server; each error shows under its field

  <TextField name="code" isRequired>
    <Label>{t.form.code}</Label><Input />
    <FieldError />
  </TextField>
</Form>
